# 浏览器能力与搬运来源采集

用户只描述业务目标，由助手读全局 `browser-task-router`、查看 `toolbox.py status`，按连接、账号、后台焦点安全和实际需求组合工具。安装完成不等于连接、登录或当前商品访问已验证。不要全部启动，也不把某个Skill当作任务能力上限。

## 已选择的分工

个人版淘宝/天猫真实搬运默认恢复已成功使用的 **日常 Chrome + WebCLI Browser Bridge + 命名任务页**。复用日常登录态，不再为此流程自动启动独立 Playwright 持久化 profile 或引导在独立窗口反复登录。Playwright 继续用于离线回归及京东公开视频；其来源读取函数只是接收已有页面的能力，不代表可以自行改选业务浏览器。用户再次明确选择其他方案时再按当前授权切换。

切回时先保存本批进度并停止旧采集控制器，仅关闭它自己的任务窗口；已有采集、逐 SKU 价格证据、商品回执、店铺专属 CLI Profile 和发布保护不回滚。先用带已维护覆盖层的 WebCLI 被动诊断连接，唯一明确的连接才可选用；连接成功不证明淘宝登录或读价成功。新建命名任务页并保存返回 target ID 后，后续读取显式传 `--tab`，禁止 `bind` 工作页，也不复用历史 context ID。

保留已有后台焦点安全失败记录，不靠换入口绕过。若当前实现首次建立任务页可能抢前台，先说明并取得该次前台操作许可；没有许可就仅完成配置切换和被动检查，不能声称已恢复真实采集。不得为恢复旧路线删除安全记录、重载工作浏览器扩展或复制登录资料。

| 环节 | 选择与原因 |
|---|---|
| 京麦身份、发布、库存、视频绑定、最终回读 | 保留官方京麦CLI，不用浏览器点击替换已验证接口 |
| 京东公开来源可直接读取的数据 | 保留HTTP路径，避免不必要的浏览器开销 |
| 公开源视频必须由页面加载才可读取 | 路由器已安装的Playwright CLI，确定性只读、全新无界面隔离会话；按视频ID捕获响应 |
| 淘宝已登录页面采集 | 已核实且符合后台焦点约束的WebCLI/BrowserSkill等现有连接，任务专属页；交换结构化JSON而不是Cookie或元素引用 |
| 未知页面探索或定位异常 | Browser-Use/BrowserSkill按需观察，先确认会话所有权；只在需要时接管并释放旧控制器 |
| 回归、网络响应检查 | Playwright CLI的独立无界面浏览器；本地拦截夹具不访问真实商家 |
| 云浏览器、Browser-Act多账号隔离、模型代理 | 当前没有必要，不自动启用云服务、付费模型或复制业务资料 |

## 已实现：公开源视频补采

`jd_product_mover.fetch_video_info_with_browser` 复用 `browser_source_read.py` 和 `browser_collectors/jd_video.js`。原先依赖临时 `npx`、固定等待5秒，并取第一条播放接口资源；页面含其他视频时缺少目标身份匹配。

现在通过 `~/.agents/skills/browser-task-router/scripts/toolbox.py run playwright-cli` 运行已安装客户端。原HTTP优先路径、高画质选择及后续视频下载/绑定不变。

- 每次生成唯一会话名，全部命令含相同 `-s`，单独临时目录、无界面、非持久化上下文；不加载个人profile、storage state或CDP连接。移除继承的Playwright连接环境变量。
- 脚本从文件传入，使用原生参数列表和UTF-8，不拼接Windows shell命令。正常采集不安装包、截图、导出Cookie或跟踪文件。
- 打开商品前等待指定JD播放接口响应，验证接口域名、视频ID及最终商品页身份；不再固定休眠后取第一条资源，也不主动重放播放请求。
- CLI沙箱不提供网页的 `URL` 构造器，响应匹配使用限定域名的纯字符串解析；不能把仅在浏览器控制台能跑的脚本当作CLI已验收。
- 超时/登录或安全拦截/结构不符时不自动换供应商或重复访问。只关闭本次命名会话；关闭未确认时报告会话名，先诊断，不启动替代会话或关闭全部浏览器。
- 独立空白会话只适合已授权的公开来源；接口明确权限拒绝不是换浏览器绕过的理由。需要登录时由助手复用现有授权连接并重新核实，不拷贝凭据。

## 已实现：淘宝结构化交接

读取 `browser_collectors/taobao_capture.js`，在已核实的任务专属商品页只读执行函数，直接保存函数返回的JSON。WebCLI等求值工具执行函数表达式时要实际调用；Playwright使用 `page.evaluate(collector)`。不导航当前工作页，不导出整个 `window.__ICE_APP_CONTEXT__`。

采集只保留所需商品、卖家标识、属性、真实SKU和逐SKU价格、图片及视频字段。当前文档内的详情图按DOM顺序保留，惰性图片取 `data-src`；详情仍必须完成业务完整性观察，不以当前节点计数替代全量验收。

`taobao_product_mvp.py --capture <采集JSON> --source-url <已解析的淘宝/天猫商品URL> --duplicate-review <本批AI判重JSON> --profile <目标Profile>` 消费结果。普通短链需先在授权任务页解析到明确商品URL；新结构不接受登录页、混合页面或未知商品ID。该命令仍可能访问目标店铺和下载素材，并非纯离线命令，不能仅为测试随意运行。

旧 `--bootstrap` 与 `--detail-dom` 输入兼容；同样新增商品ID一致性和非空真实SKU保护。来源捕获不会扩大店铺、类目、发布或生图授权。任何发布仍保留商家编码、定价、A/B一致性、状态幂等和独立回读。

## 已实现：京东源逐SKU到手价接口采集

需要京东源的逐SKU到手价（优惠后）时，在已登录任务页上下文内直接调用商详接口批量读取，不逐页切换商品。

- 失败表现：PC价格区为 closed shadow DOM，DOM查询不稳定；逐SKU翻页读取约10次导航内触发软风控——先踢登录、后仅渲染页面骨架，暂停90秒不恢复。逐页方式94秒仍未读完9个SKU。
- 解决方式：在已登录 WebCLI 任务页（item.jd.com 同源上下文）单次 `eval` 内循环对全部SKU调用 `https://api.m.jd.com/?functionId=pc_detailpage_wareBusiness&body=<URL编码JSON>&loginType=3&appid=pc-item-soa&clientVersion=1.0.0&client=pc`，`fetch(..., {credentials: 'include'})`。该参数组合无需 h5st 签名；`area` 取当前页面请求中的地址码。解析 `bestPromotion.purchasePrice` 为到手价、`price.p` 为京东价；`canGetCoupon` 可核对券规则。
- 边界：请求必须复用已授权登录会话的页面上下文，不导出Cookie或复制登录资料；仅打开一次任务页，接口循环不产生页面导航。接口返回错误或缺失 `bestPromotion` 时停止并留证，不降级为快速翻页（风控触发路径），不按券面额猜其他SKU价格后当作已验证展示价。
- 验证：2026-10-08 商品10234348547697全部9个SKU共3.3秒完成；`purchasePrice` 109/59/56 与页面展示（¥59到手价）、输入表格行到手价59及商品级满20减6券推算全部一致。淘宝侧等价方案见 `taobao-source-adapter.md` 的 `skuCouponInfoWithQuantity`。
- 同一响应的 `colorSizeVO.colorSizeList`（维度1颜色 `buttons`）带 `no` 字段，即前台SKU展示顺序（主推款顺序）。生成或重排商品信息表时，SKU行必须按该顺序排列，不按采集器/`newColorSize` 返回顺序。商品级字段（标题、货号、商品属性、类目）只保留在排序后首行。2026-10-08 商品10234348547697验证：前台顺序 单人灰/黑/米→双人灰/黑/米→亲子灰/黑/米，与采集器默认顺序（亲子黑起）不同，重排后逐行回读校验通过。
