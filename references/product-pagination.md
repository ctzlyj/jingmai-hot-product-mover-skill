# 商品分页完整性

## 触发与根因

全店盘点、查重或审计调用 `GET /rest/sp-product/v0/products` 时，即使累计行数等于 `paginationData.totalItems`，默认排序仍可能使相同商品跨页重复，导致其他商品缺失。仅累加行数会误报完整。本地只读复现后，显式按创建时间升序查询通过前后两轮唯一性和商品集合比对。

## 可靠步骤

1. 先验证店铺身份并配置具名 Profile；只调用官方 CLI 的只读接口。
2. 调用 `jd_product_pipeline.list_products`，保留原业务筛选条件，固定 `sortBy=created`、`sortType=asc`、`pageSize=50`。
3. 每页验证总量和页码，发现缺失/重复商品 ID、总量变化、提前空页或数量溢出即停止。不得用去重后的不完整结果继续发品、覆盖或生成“全量”结论。
4. 对唯一商品逐个用 `scene=pop` 查询详情的完整 `skuList`。平台 SKU ID 才是集合键，不能用可能在多个商品中重复的商家编码代替。
5. 对时效敏感的导出，再次枚举并比较商品 ID、修改时间和状态；变化时重新只读采集，不自动重试任何写入。

## 回归与验证

在 Skill 根目录执行 `python -m unittest discover -s tests -p test_product_pagination.py`。覆盖稳定排序、筛选保留、重复 ID、提前空页、总量漂移、缺失元数据和正常空结果。修复前六项测试中五项失败；修复后全部通过。完整盘点必须另做具名 Profile 的只读实测，并核对商品详情 SKU 去重数。

## 保留、合并与停止

此修复位于个人 Skill 和维护项目的 CLI 调用层，没有修改官方 CLI 安装包，也不是 WebCLI 站点适配器覆盖。

本次三方合并的仓库基线为 `4f9fabcb656d53771cb76d7e94c74c9c1f3ff68b`。上游更新时，以该 Git 版本对应文件为共同祖先，当前工作树为本地版，下载到独立候选目录的新版为上游版。仅自动替换本地未修改文件；保留本地独有的本说明和分页测试；双方都修改 `scripts/jd_product_pipeline.py` 或 `SKILL.md` 时必须保留本地，先完成三方语义合并再跑回归。禁止 `reset --hard`、全目录覆盖安装或删除本地增强。不得用其他版本的整份流水线覆盖本地已有业务修改。

合并后的回归或只读全量验证失败时，不替换现有工作版本。排序只降低分页漂移风险，不承诺同一创建时间下绝对稳定；完整性检查失败必须停止，不能静默去重后声称完成。
