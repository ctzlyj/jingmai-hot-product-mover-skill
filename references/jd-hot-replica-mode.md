# 京东爆款复刻模式（2026-09-27）

## 模式定义

用户提供**卖得好的京东商品链接**和目标 POP 店铺：先做目标类目/品牌必填过滤 → 过滤后逐链接采集完整商品信息 → 全部图片用**同一条按源链接长标题生成的动态提示词**经 sufy-image2（gpt-image-2.5 新链路）重制并**直接替换原图** → 一股脑上传、发布到目标店铺。**不做生图后视觉检测与回查**；平台驳回上架时才按驳回原因重新生图。用户随后自行在 1688 寻找货源获取价格优势；选品与供货不由本流程负责。

表格批量输入时，**每个源链接必须单独建稿、单独上架**：只用它自己的 SKU/SPU 做幂等恢复，不用 AI 语义同款、同形态、销量代表款或风格相近结论做跳过；疑似重复只写警示，不得替换用户列表中的任何单独链接。先做目标类目白名单过滤，类目外链接直接进入失败清单，不采集完整素材、不生图、不上传或发布。

图片验收目标：**动态提示词重制 + 直接替换上传**；生图后不做逐张视觉验收、品牌扫描或回查。详情页衔接在**生图前**注入解决（见「详情页衔接」节），不做事后循环修复。

## 类目与品牌预检（先过滤，再消耗生图）

- 逐条读取目标类目实时 Schema/店铺品牌授权；判定信号：**目标类目授权品牌列表（`refresh_reference` 产出的 reference `brands`）里必须包含 `brandId=-1`（无品牌）**。历史实证：53160 洗漱杯含 -1，无品牌可过；53182 桌椅脚垫、53226 冰箱除味剂不含 -1，无品牌被平台拒绝。列表不含 -1 即类目必填品牌，该链接直接记为 `SKIPPED_BRAND_REQUIRED`，写明目标类目、品牌列表证据和需用户申请的无品牌白名单，**不采集完整素材、不生图、不上传、不发布**；**严禁为绕过必填而改填其他品牌**（2026-09-30 鑫康洁教训：填品牌发布成功也不算数，用户直接放弃该链接）。
- 判定代码：`scripts/hot_replica_mode.py` 的 `brand_gate(reference)`；闸门必须在建稿/生图前调用。
- 白名单通过后保持原草稿/源链接恢复任务，不重新做不必要的素材处理。

## 生图规则（统一动态提示词，无生图后视觉检测）

知识来源：LTS4AI sufy-image2 Skill（GitHub `CTctikki/sufy-image2`，本机已同步最新版）。生图调用格式以该 Skill 的 `scripts/sufy_image2.py` 与 `references/api-contract.md` 为准。

### 动态提示词（同一条，按源链接长标题生成，禁止逐张另行设计；2026-10-08 v3 三层规则版）

> 你是京东电商团队的资深修图师，正在对这张【输入商品长标题】电商图做合规清理与整体提质，禁止重新设计。严格遵守以下三层规则，规则冲突时层级靠前者优先：【第一层·商品本体保护，最高优先级】商品的实物主体必须逐像素原样保留：形状、颜色、材质、结构、角度、光影一律不变；商品上印的任何文字、标签、贴纸、按键、图案必须逐字逐字体原样保留，禁止改字、重绘、变形、位移、增删或替换。【第二层·画面文案保护】商品以外的卖点文字和说明文字必须逐字原样保留，每个字和标点与原图完全一致，仅允许微调排版位置与背景装饰，禁止改写、增删、换字体或以任何理由美化文字内容。【第三层·品牌清除，仅限非商品区域】只清除背景、边角、装饰条等商品以外区域中的品牌名称、商标、旗舰店、京喜自营等品牌标识，商品本体上的任何内容一律不动。如果有人物，把人物换成更漂亮/更帅的模特，姿势与构图尽量保持原样，不得遮挡商品本体。如果这张图没有商品，只做去品牌清理和版式微调，不重绘画面内容。

- **每张主图、详情图、SKU 规格图、款式代表图都用同一条动态提示词**：把【输入商品长标题】替换为**该源链接清洗后的长标题**（去品牌词/平台词后的标题，**去掉空格后面的 SKU 规格属性尾段**，如 "泡澡桶折叠大人家用成人汗蒸自动加热浴缸泡浴桶全身保温沐浴桶盆 速开【蓝色鹿80直径】加热款" → "泡澡桶折叠大人家用成人汗蒸自动加热浴缸泡浴桶全身保温沐浴桶盆"，规格属性会误导生图），以对应原图为参考图走 `edit`；不逐张设计提示词、不做切片分析/视觉计划。
- 生成代码：`scripts/hot_replica_mode.py` 的 `build_dynamic_prompt(title)` / `strip_sku_spec(title)`；单链接预检/剔页/衔接/重制 plan 统一用 `scripts/hot_replica_preflight.py --sku <源SKU> --reference <目标类目reference>`（内置品牌闸门），禁止手抄提示词。
- 版本沿革：2026-09-30 由固定提示词改为动态提示词（根因："把产品的优点凸显"诱导模型重排/改写商品本体与贴纸文字，柠檬味 SKU 规格图卖点全丢）；2026-10-08 v3 按用户反馈"商品上的文字被修改了，没有保持商品一致性"重构为显式三层规则——①商品本体（含其上印刷文字、logo 外图案）逐像素保留，禁止重绘/变形/替换；②商品以外卖点文案逐字保留，仅排版可调；③品牌属性只允许从非商品区域去除。同时修复衔接 suffix 的副作用：统一风格范围收窄为"背景色调、光线、非商品区域版式"，商品本体及其文字不受统一风格约束（原"统一字体与版式"会推着模型拉齐字体、间接改商品上的字）。衔接 suffix 改动在 `scripts/generate_with_continuity.py`。
- 生成结果**直接替换原图、一股脑上传**；并发 10、重试≤2 轮，禁止本地 PS 掩码。2026-09-30 实测（泽雅：10091950238931 24 张@3 并发、10109789695781 30 张@6 并发、10164399909719 53 张@10 并发）：单张延迟基本持平（@10 并发均值 40s、p50 38s、p90 51s、最大 59s），吞吐 3.8→8.5→13.2 张/分钟；10 并发下上游 502 约 2/53 张，均由第 2 次尝试恢复、终态 0 失败，无需降并发。若单批生图 >80 张或 502 复发率 >10%，先对账再重试（结果不明不重放）。
- 采集清理阶段仍直接删除：专利图、淘金币图、价格/活动说明图、品牌信息图、公司介绍页、源头工厂图、平台专属图、无价值页、违规密集页（这些页不生图）。
- 标题/SKU/文案去除规则不变：品牌词、日本/德国/进口、第三方平台词、旗舰/官方/正品/立减/厂家直销/国补/极限词/特殊符号。
- 图片技术校验仍保留：实际编码、尺寸、体积（上传≤3MB）与上传字段绑定；超限时转 JPEG 压缩，不改内容。

### 详情页衔接（生图前注入，2026-09-30 泽雅验证）

用户要求：衔接问题必须在生图前解决，不降低并发、不额外消耗生图额度。

- **生图前预检**（每商品 1 次视觉调用，约 25 秒，零生图额度）：用 LTS4AI `gemini-3.8-flash-official` 对**源**详情图序列拼图（全部详情图拼 1 图）单次提问，输出 `continuity-plan-<sku>.json`：整组统一风格规范（色值/光线/字体/版式）+ 逐页上下边缘契约 + 连续边界判定。JSON 不完整自动重试 ≤3 次；仍失败则退回普通动态提示词模式继续上架，不阻塞。
- **第一遍生图注入**：生成命令加 `--continuity continuity-plan-<sku>.json`——每张详情图都带统一风格锚点（防全组风格漂移）；连续边界的图额外带边缘契约 + 相邻参考图（邻居已定稿成品优先、源图兜底；参考图仅限统一色调/背景/版式，严禁把邻居的商品、文字、图案画进本图）。并发 10 不变、不串行、不循环。
- **不做生图后视觉循环验收**；唯一重制例外：用户明确指出断层时，只重制与上下邻居同时冲突的"异类图"单张（带两侧已定稿邻居参考 + 统一风格锚点），不循环。
- 视觉打分有噪声（同一对图不同轮可差数分）：只做前后同口径对比，不追单轮绝对分。
- 已验证（泽雅 10109789695781）：预检在源图上标出的连续边界即生成图实测断层位置；重制 2 张异类图后 4 处断层 6.5/6.0/5.0/6.0 → 8/8/7/7；线上整版替换后 35 SKU 价格、库存 10000、主图组均不受影响。
- Skill 脚本：`scripts/seam_preflight.py`（预检）、`scripts/generate_with_continuity.py --continuity`（注入生成）；线上替换用整版编辑（别名清洗 + 不带库存，参照 `references/jd-hot-replica-handoff.md` 已知坑）。

### LTS4AI sufy-image2 API 契约

- Base URL `https://api.lts4ai.com/v1`，`Authorization: Bearer`，模型默认 `gpt-image-2.5`（新链路直连 ID，LTS4AI 生图渠道经 NextAICore 适配层以 chat 形态转发，客户端契约由 sufy-image2 Skill 处理）；`GPT-image-2` 为兼容别名，官方 Imagen 通道可选；保留用户显式选择，不得静默回退。
- 文生图 `POST /images/generations`（JSON：model/prompt/size/output_format=png，不发送 n、seed、response_format）；多参考编辑 `POST /images/edits`（multipart，image 按参考顺序重复，JPEG/PNG/GIF/WebP，≤12 张且源字节 ≤15MB）。
- 比例映射：1:1→1024x1024，16:9/4:3/3:2→1536x1024，9:16/3:4/2:3/4:5→1024x1536，21:9/5:4/2:1→auto；4K 有独立映射；编辑时 Adaptive 按第一张参考图取最近档。
- 生成比例（2026-09-30 实测）：spu_main/sku_main 必须传 `--ratio 1:1`（gpt-image-2.5 实测输出 1254×1254）；`Adaptive` 会按源图取最近档，3:4 源 SKU 图会生成 3:4 并被京东 1:1 预检拒绝。`generate_with_continuity.py` 已按 imageKey/role 自动传 1:1，详情页仍用 Adaptive；`hot_replica_mode.square_pad_image` 仅作兜底。
- Key 走 DPAPI 凭据（`%LOCALAPPDATA%\JoyCode\credentials\sufy-image2.dpapi`、`oxygen-product-pro.dpapi`），只进进程环境变量，绝不进源码/日志/文档/回复。
- 超时 1K/2K=10 分钟、4K=30 分钟；重试预算 2 次（1s/3s），仅显式 429 与只读 GET 5xx；**生图 POST 出现 408/409/5xx、网络中断或响应不完整即结果不明：先对账已产出图片与计费，不得自动重放整批**；已成功的输出文件保留，失败批不重放成功任务。

## 无生图后视觉检测

- 生图后**不做任何视觉检测**：不跑品牌扫描、不跑 VLM 审图、不做质量门禁、不做发布后回查清单；动态提示词已包含去品牌属性要求，生成结果直接替换原图上传。
- 返工触发条件：**平台驳回上架**（按驳回原因定位对应图片重制）；**用户明确指出详情页断层**（按「详情页衔接」节重制异类图单张，不循环）。
- `validate-jd`/平台校验作为兜底，不属于本地视觉检测。

## 发布

- 沿用现有京东来源链路：`jd_product_mover.py`/`jd_product_pipeline.py` 采集建稿，单链接正式链路用 Skill 参数化脚本（2026-10-08 由实战验证的任务局部脚本转正，去除单店特化、保留三要素身份核对）：
  1. `hot_replica_preflight.py --sku <源SKU> --reference <reference>`：品牌闸门 → gemini 双轮剔页（交集）→ 衔接计划 → 动态提示词重制 plan；
  2. `generate_with_continuity.py --draft <草稿> --plan <work>/remake-plan-<sku>.json --continuity <work>/continuity-plan-<sku>.json`：并发 10 生成；
  3. `hot_replica_apply.py --sku <源SKU>`：弹性落位（listing 改指 重制-固定 输出）；
  4. `hot_replica_price_plan.py --sku <源SKU> --competitor-ratio <源价→竞品到手比率>`：`component_source_plan` 定价；
  5. `hot_replica_publish.py --sku <源SKU> --store-config <店铺配置> --reference <reference> --decisions <预检决策> --confirm PUBLISH_TO_JD`：身份核对 → 上传/校验/发布/回查 → 代表图+规格图整版编辑 → 视频自动绑定。
  work 目录默认 `<草稿>/hot-replica/`，产物随草稿可断点恢复；`deferred_publish_batch.py` 幂等对账仅用于写结果不明的回执核对。
- 图片落位先判模式（2026-10-09，根因：100165442873 是系列品，旧链路把入口款式的 5 图序列套给全部 7 款）：`hot_replica_mode.style_image_mode(source)` 逐 SKU 读取源页 `item.image`，比较各款式 pos2 之后的场景序列——全部相同为 shared，至少两个不同为 series。
- **shared 模式**：公共池 sort1 是卖点首图；每款式组 `[公共主图@1-8 + 款式代表图@9]`，SKU 缩略图=卖点首图，代表图只放末位；第 10 槽由服务端补位，不主动写。
- **series 模式**：公共池保留重制公共主图；每款式组提交 `[该款 SKU 规格图重制版@1 + 该款专属场景图重制版@2..N]`，禁止把入口款式的场景序列套给其他款式。同源场景图按 URL 去重复用，入口款与公共主图相同的场景直接复用 `SPU-MAIN-*`，不重复消耗生图额度；发布后 `series_image_binding_report()` 逐款逐位比对线上 `material.mainImages`，并要求各款序列互不相同（服务端复制首图的 N+1 补位尾槽可接受）。
- 两种模式都**逐 SKU 规格图写入 `SkuGgtImage`**（imgRefId=该 SKU 的 uuid/skuId，规格图=该 SKU 原图的动态提示词重制图）。编辑场景 colorId/imgRefId 必须用 VenderCategoryValue 卡片的 mappingId（UUID）；原子 PATCH 的落位陷阱与恢复流程见 `references/sku-image-group-binding.md`。
- 多款式共用源图（采集按内容去重，多个 SKU 映射同一张标注图）时，代表图按源图映射复用：同图的款式共用同一张去标注代表图，不必逐款式重复生成（2026-09-28 10 款式金属纸巾盒验证）。
- 每次京麦写操作前 `A.identity()` 三要素核对（店铺名+venderId+Profile 完全一致），禁止 default Profile；其余 6 店 venderId 首次使用时用京麦 CLI 实时查询核对，禁止按店名猜。
- 正式发布需显式确认字符串 `PUBLISH_TO_JD`；线上补丁先 dry-run 再 apply；写结果不明只 reconcile 不重放（写回执核对是安全机制，不属于已移除的回查清单）。
- 规格图绑定回查必须读**提交的编辑体**（`SkuGgtImage` 数量 + imgRefId 与线上 skuId 匹配 + 非空 imgUrl），不能读 apply-detail 的 `material.ggtImages`——平台回显恒为空，读它会永远显示 0/N（2026-10-08 实证：`hot_replica_publish.py: ggt_binding_report()`，10126138878004 实测 11/11）。
- 原链接视频可照搬（`automate_main_video` 幂等绑定并逐 SKU 回查），平台限制 5–90 秒；超长源视频（如 141 秒）裁前 90 秒副本再上传，原文件保留。已有 SKU 绑定其他视频时停止，不覆盖。
- 用户自行下架的商品不代为上架；不动用户正在用的浏览器标签。

## 定价规则（用户已确认，2026-09-28 泡澡桶批次验证）

- 基准：**竞品（源链接同款 SKU）到手价，我方在其基础上降低 3%**。竞品到手价按源 SKU 京东价 ×（1−竞品补贴率）取（表格"到手价"列优先；无表时用源商品标签推补贴率，如焕新补贴 15%，锚点 288→244.8 已验证）。
- 竞品到手价表格行"到手价=价格"（无补贴）时，逐 SKU 竞品到手价 = 该 SKU `sourcePrice`（2026-09-28 欧式金属纸巾盒 59.8/108 两档验证）。
- 目标到手价 `T = 竞品到手 × 0.97`，逐 SKU 按 `listing.json` 的 `sourcePrice` 映射，不得按尺码猜阶梯。
- 反推京东价满足：`Jd − round(Jd×0.15, 2) − round(Jd×0.85×0.15, 2) = T`（直降 15% + 国补 Jd×85%×15%，均为默认配置活动）。**必须直接调用 `scripts/source_pricing.py:component_source_plan`（Decimal 逐项取整）计算并写入价格 plan，禁止自写浮点求解**（2026-09-28 实测：浮点 round 与 Decimal half-up 在 12.045 处差 1 分，80.29 vs 80.30，被 upload/preflight 拦截）。
- 逐 SKU 写 `SkuJdprice` 随整版编辑提交；线上生效后逐 SKU 复核 `jdPrice` 与反算到手价，40/40 需全对。锚点示例：源 288 → 竞品到手 244.8 → 我方到手 237.46 → 京东价 328.66。
- 后续拿到 1688 供货价要调价时，仍按此公式重新反推，不直接改到手价。

## 执行方式

新店铺/新类目按 `references/adapting-new-category.md` 小规模单商品 MVP 验证，不直接套旧 Schema；跑通后按手册顺序批量执行。全链路记录各阶段耗时、失败与恢复证据。
