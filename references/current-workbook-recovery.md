# 商家补码后的网络盘读取与规格差异

## 网络盘旧长度缓存

### 已复现的失败场景

商家替换同名XLSX后，映射盘符仍报告旧长度和旧修改时间，却读取到新版文件头；完整读取被旧EOF截断，`openpyxl` 报 `File is not a zip file`。文件可能有ZIP头但缺中央目录尾，也可能因新版更短而返回空字节。这是读取完整性失败，不能据此判定商家没填编码。

负例验证：保留失败字节、长度及SHA-256；ZIP完整性检查失败时不读商家码、不提交商品。不要修复ZIP目录或猜测缺失内容来绕过源文件完整性要求。

### 已验证的恢复步骤

1. 用 `Get-CimInstance Win32_LogicalDisk` 查询该盘符的 `ProviderName`，只使用同一个已授权映射对应的UNC根，不另找账号或其他共享盘。
2. 通过该UNC路径**枚举每个目标商品的父目录**，触发目录元数据刷新。仅改用UNC或仅对文件执行 `Get-Item` 不一定刷新其他目录；目录枚举本身也可能先返回旧值。
3. 有界等待后重新读取文件元数据和完整字节，校验ZIP全部成员CRC，再运行工作簿表头、来源ID、商家码、完整规格集合校验。源文件路径及实际字节SHA-256重新绑定计划，旧计划不能继续提交。
4. 本次真实回归中，8份原先截断的读取全部恢复为完整、CRC通过且可解析的当前文件；恢复只涉及读取，没有更改源文件或驱动配置。
5. 仍不能获得完整文件时停止该项，报告“当前源文件读取不完整”，请求用户刷新或重连网络盘；不自动断开共享盘、不停服务、不删除缓存、不改全局缓存配置。

可使用以下原生命令只读刷新指定目录，路径必须先核实属于用户授权来源：

```powershell
$source = 'X:\商品目录\价格计算模板.xlsx'
$drive = $source.Substring(0, 2)
$disk = Get-CimInstance Win32_LogicalDisk -Filter "DeviceID='$drive'"
if (-not $disk.ProviderName) { throw '没有可核实的映射UNC根' }
$unc = $disk.ProviderName.TrimEnd('\') + $source.Substring(2)
Get-ChildItem -LiteralPath ([System.IO.Path]::GetDirectoryName($unc)) -Force
Start-Sleep -Seconds 3
Get-Item -LiteralPath $unc
```

最后必须由工作簿读取器验证完整ZIP及实际行值，命令执行成功或文件存在不是验收标准。

## 补码同时改了规格文字

默认完整规格匹配仍然严格，不能按行号或相似度自动套码。若只是明确的多余字修正，逐行确认款式、所有尺寸数字、单位、材质和赠品均一致，保存“原完整属性 → 当前完整属性”的有限映射及理由，然后将当前表的商家码绑定到历史平台SKU ID。不要做全局字符串替换；线上销售属性仍从实时详情原样提交，不能顺带修正文案。

## 当前表删掉一个已有选项

表中有明确完整对应关系的SKU可以在已授权范围内继续纠码；缺行SKU单独保留，不生成编码、不删除或下架。请求仍携带全部原SKU ID且不含库存：`make_full_edit` 支持仅对目标子集修改编码，其余SKU原样带回。

计划必须区分“有商家目标码的SKU集合”和“仅保持原值的缺码SKU集合”。回读检查全部SKU：目标子集等于商家码，保留子集等于编辑前原码，其他业务字段和库存不变。最终分别统计整SPU完成、部分完成及未确认的SKU，绝不能把“保留了旧自动码”算成商家编码已确认。真实验证已覆盖同SPU多个尺寸已纠正、无尺寸缺行选项保持原值的A/B两条链接。
