# 故障处理与停止条件

## 必须停止

遇到以下任一情况，不得继续正式发布：

- 当前 `venderId` 或 `shopName` 与 `store.local.json` 不一致。
- 店铺已有商品未完整读取、AI 语义判重不可用或判重证据记录无效。
- 源商品或素材无合法使用授权。
- 源 SKU 列表不完整，或任一 SKU 的 `priceFloor.ext.jdPrice` 缺失。
- 价格 K/L 复算不一致，或预计到手价不等于源价减默认差额。
- 实时 Schema 缺失、过期，或规则中的属性值不在当前 Schema 中。
- 销售属性维度数量无法确定。
- 图片文件缺失、格式不支持或超过接口限制。
- 视频文件缺失、时长或大小不合规。
- 任一 SKU 已绑定不同主图视频。
- 商品详情、库存、主图或视频关系审计失败。

## 常见问题

### Python 捕获 jdo-cli 后中文变成替换字符

Windows 管道模式下必须同时给 `jdo-cli` 子进程设置 `PYTHONUTF8=1` 与 `PYTHONIOENCODING=utf-8`，并按原始字节捕获；优先严格 UTF-8 解码，失败时回退 `gb18030`。只设置 `PYTHONIOENCODING` 仍可能得到 `����`。标题或属性中存在替换字符时停止 AI 判重和发布。

### 标题规则造成误判或漏判

标题标准化、关键词、编辑距离、哈希和字符串精确匹配只能用于召回候选，不能直接决定重复。应回到原始标题、类目、核心含义、图案款式、形态材质、用途、销售属性和必要图片，由 AI 生成结构化结论。AI 判定重复时记录并继续下一条；证据不足时判 `PROCEED`，不得强行跳过。批次结束统一报告匹配对象和理由。

### 批量命令绕过 AI 判重

`batch` 必须传入 `--preflight-decisions`。脚本会在调用任何单品流水线前确认输入中的每个源 SKU 都有 `PROCEED`、`SKIPPED_OUT_OF_SCOPE_CATEGORY` 或 `SKIPPED_AI_DUPLICATE` 决策；缺失或字段无效时整体停止。跳过决策遇到已有 `productId` 时也停止，必须按原商品恢复，不能把已创建商品改写为跳过状态。

### 用户改判后状态仍显示旧跳过原因

用户明确改变目标类目或 AI 判重结论后，可复用原源 SKU 状态恢复。进入任何非 `SKIPPED_*` 阶段时清除顶层旧 `categoryDecision`、`preflightDecision` 和 `duplicateReview`；历史阶段仍保留在 `history`。验证最终状态不再同时出现 `VERIFIED`/`PUBLISHED` 与过期跳过原因。

### 大请求体无法启动 CLI

Windows 命令行长度有限。不要把大型 Schema 或 Base64 直接放入 `--body` 参数；使用 `jdo_large_body_bridge.py` 从 UTF-8 文件读取，并继续复用原版 `jdo-cli` 的凭据与签名逻辑。

停止条件：找不到 Python 3.12、无法读取原版 CLI 运行时或凭据不可用时，不要改成自建签名。

### 新品发布后详情暂时查不到

发布响应一旦返回 `productId`，立即写入状态文件。详情接口返回“未查询到商品信息”时，先查询 `/rest/sp-product/v0/product-apply/{applyId}`，不能直接假定为索引传播延迟。申请未驳回时仅轮询该 ID；有限轮询耗尽写入 `PRODUCT_PROPAGATION_PENDING`，外层异常处理必须保留该阶段和 `productId`，不能覆盖为普通 `FAILED`。

验证方式：状态文件包含原 `productId` 且阶段为 `PRODUCT_PROPAGATION_PENDING`；复跑时跳过图片上传、合规校验和新增商品接口，只查询该商品。停止条件：标准商品详情仍不可查时保留状态并等待平台传播或人工工单，不得清空状态、删除申请或重新创建。

### 合规驳回被误判为传播延迟

失败表现：发品接口返回 `productId`，标准详情持续不可查，但申请单详情的 `draftComputeStatus=3`，申请列表同时常见 `status=300`、`keeperStatus=309`、`pushStatus=100`。这表示草稿审核/合规驳回，不是传播延迟。

可靠步骤：立即写入 `PRODUCT_APPLY_REJECTED`，保留 `productId` 和申请状态并停止轮询。开放接口未返回 `auditReason` 时，可在白名单店铺的京麦“商品审核 > 查看驳回详情”中使用独立后台标签只读核验具体违规模块；不得导航用户当前标签。若违规来自详情图，保留原图归档，生成合规副本并保持详情图数量与顺序。

验证方式：同一状态复跑在首次详情失败后即可识别驳回，不再等待完整传播轮询；外层异常处理保持 `PRODUCT_APPLY_REJECTED`，不覆盖为 `FAILED`。停止条件：若驳回新品尚未进入商品库，PATCH 报 `SKUS不存在`、整版编辑报“查询编辑的商品信息失败”或京麦原 `wid` 编辑页显示“商品不存在”，不得清空 `productId`、删除申请或自动重建，需由用户明确决定后续处置。

### 成功状态仍显示旧错误

失败后恢复成功时，最终审计可能已经通过，但状态文件仍残留旧版流程写入的 `error` 或 `errors`，造成“`VERIFIED` 同时显示失败”的冲突。根因是旧版成功状态只清理了部分瞬时错误字段。新版 `save_state` 在任何非 `FAILED*` 阶段同时清理 `error` 和 `errors`，历史阶段仍保留在 `history`；复跑一次只读恢复/审计即可规范旧状态，已有 `productId` 时不得重新创建商品。

验证方式：回归测试从含 `error` 与 `errors` 的 `FAILED_LOCAL_VALIDATION` 状态写入 `VERIFIED`，确认两个字段均消失且 `history` 正常追加。停止条件：最终 `verification.json` 不是 `ok=true`、线上审计仍失败或 `productId` 不明确时，不得仅靠清理字段宣称成功。

### 商品列表 SKU 不完整或顺序变化

商品列表只用于定位商品。最终审计必须使用详情接口的完整 `skuList`，不能依赖列表页的 SKU 分页或排序。

### 淘宝宽高尺寸被错误压成单边长度

失败表现：源尺寸为“宽60厘米-高40厘米”或“宽60厘米---高30厘米”时，本地 `sizeAlias` 被错误写成 `60cm`，丢失高度。根因是宽高识别只接受 `x`、`×`、`*` 分隔，未覆盖淘宝常见的单连字符、多连字符和长横线。可靠步骤：宽高解析同时接受 `-`、`---`、`—`、`–`，统一规范为 `60×40cm`；重新生成尚无 `productId` 的本地草稿并复核全部尺寸组合。已有 `productId` 时禁止重建商品，应停止并按原商品修正。

验证方式：回归测试覆盖单连字符和三连字符；本地草稿的 8 个真实尺寸保持完整，发布后完整 `skuList` 的组合数量、价格和商家编码审计通过。停止条件：任何宽高规格仍退化为单边长度、尺寸组合数变化或已有商品 ID 时，不得继续新增发布。

### 已有商品编辑导致库存翻倍

已有商品整版编辑时删除所有 `SkuStockNum`。绝对库存只通过库存专用接口的 `fullStockIn` 修改，单批最多 20 个 SKU，并先查询真实仓库与门店 ID。

### 多套主图补图错位

每个颜色组提交完整数组，位置 1 带回现有专属首图，位置 2–10 填公共图。不能把多个颜色组摊平成一个组件，也不能只提交位置 2–10。

### 视频复跑卡在转码

审核通过后视频素材状态可能为 `4`，不仅是转码完成状态 `2`。两者都应视为可复用；状态 `5`、`6` 视为失败。

### 大 SKU 商品查询视频素材失败

`GET /sp-product/v0/sku-materials` 单次最多传入 50 个 SKU。查询已有绑定前必须按 50 个 SKU 分批并合并结果；不得因该查询失败而重新上传视频或重新创建商品。

### 大 SKU 商品的视频关系被误判为缺失

`GET /sp-product/v0/media-zones/{zoneId}/video-sku-rels` 默认只返回第一页。必须根据 `paginationData.totalItems` 逐页读取全部关系；不得拿第一页最多 50 条与完整 SKU 清单直接比较。

### 视频关系一直待审

保存 `VIDEO_REVIEW_PENDING` 和所有 ID，停止重复提交。稍后复跑只查询关系。如果被驳回，输出 SKU 列表和审核状态，交给用户处理。

## 回滚原则

- 在创建商品前失败：修正本地素材或配置后复跑。
- 创建商品后失败：保留商品 ID，继续修复或审计，禁止新建第二个商品。
- 视频绑定异常：先查询关系事实，再决定是否补绑；禁止根据单次 HTTP 错误盲目重试解绑。
- 不自动删除商品、不自动覆盖已有视频、不自动修改营销活动。
