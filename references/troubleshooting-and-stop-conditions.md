# 故障处理与停止条件

## 必须停止

遇到以下任一情况，不得继续正式发布：

- 当前 `venderId` 或 `shopName` 与 `store.local.json` 不一致。
- 源商品或素材无合法使用授权。
- 源 SKU 列表不完整，或任一 SKU 的 `priceFloor.ext.jdPrice` 缺失。
- 价格 K/L 复算不一致，或预计到手价不等于源价减默认差额。
- 实时 Schema 缺失、过期，或规则中的属性值不在当前 Schema 中。
- 销售属性维度数量无法确定。
- 图片文件缺失、格式不支持或超过接口限制。
- 视频文件缺失、时长或大小不合规。
- 任一 SKU 已绑定不同主图视频。
- 商品详情、库存、主图或视频关系审计失败。

## 常见问题

### 大请求体无法启动 CLI

Windows 命令行长度有限。不要把大型 Schema 或 Base64 直接放入 `--body` 参数；使用 `jdo_large_body_bridge.py` 从 UTF-8 文件读取，并继续复用原版 `jdo-cli` 的凭据与签名逻辑。

停止条件：找不到 Python 3.12、无法读取原版 CLI 运行时或凭据不可用时，不要改成自建签名。

### 新品发布后详情暂时查不到

发布响应一旦返回 `productId`，立即写入状态文件。详情接口短时返回未查询到，通常是索引传播延迟；仅轮询该 ID，不能重新提交创建。

### 商品列表 SKU 不完整或顺序变化

商品列表只用于定位商品。最终审计必须使用详情接口的完整 `skuList`，不能依赖列表页的 SKU 分页或排序。

### 已有商品编辑导致库存翻倍

已有商品整版编辑时删除所有 `SkuStockNum`。绝对库存只通过库存专用接口的 `fullStockIn` 修改，单批最多 20 个 SKU，并先查询真实仓库与门店 ID。

### 多套主图补图错位

每个颜色组提交完整数组，位置 1 带回现有专属首图，位置 2–10 填公共图。不能把多个颜色组摊平成一个组件，也不能只提交位置 2–10。

### 视频复跑卡在转码

审核通过后视频素材状态可能为 `4`，不仅是转码完成状态 `2`。两者都应视为可复用；状态 `5`、`6` 视为失败。

### 视频关系一直待审

保存 `VIDEO_REVIEW_PENDING` 和所有 ID，停止重复提交。稍后复跑只查询关系。如果被驳回，输出 SKU 列表和审核状态，交给用户处理。

## 回滚原则

- 在创建商品前失败：修正本地素材或配置后复跑。
- 创建商品后失败：保留商品 ID，继续修复或审计，禁止新建第二个商品。
- 视频绑定异常：先查询关系事实，再决定是否补绑；禁止根据单次 HTTP 错误盲目重试解绑。
- 不自动删除商品、不自动覆盖已有视频、不自动修改营销活动。
